# 固定分支历史问题审查

以用户指定的基线分支或其他分支为唯一被审版本，冻结仓库身份、分支名及完整提交SHA，使用其对应有效规范、配置和资源。覆盖该固定树的实际功能和已授权范围，主动查未变更模块、正常和异常路径；不依赖其他分支的差异。问题在本分支存在不等于已知何时引入，不伪造早期对照、历史引入提交或责任。

无对照时 `review_kind: branch_history`、`target: 固定完整SHA`、`baseline: 不适用（单分支审查）`、`baseline_ref: 不适用`，发现的 `origin: unknown` 并写明引入时间未知；仍可基于完整证据确认该分支存在缺陷。用户提供更早固定对照时，可另按同场景与适用规范核证发生时间，但不得把未证问题标成基线已有。不要把同一SHA当伪基线，也不将无法比对当缺陷本身待确认。

读取并遵守共享工作流 `${CODEX_HOME:-$HOME/.codex}/skills/game_ai_review_shared/WORKFLOW.md` 及其所链接参考；本入口范围优先于共享流程的通用表述。冻结入口skill与共享工作流/工具的实际内容及哈希；发现、反证、严重度、具名核证、覆盖和独立性标准与合并审查相同。用户不提供额外基线时，用 `git ls-tree`、`git show`/`cat-file` 或API按目标SHA构建单树索引；现有 `git_snapshot.py` 的双版本接口不能传虚构基线。

使用共享 `scripts/report.py` 与 `scripts/bundle.py` 按工作流交付。`review_kind` 使首页显示“被审分支”和“无对照”的单分支语义，不展示新增/历史对比卡；四项报告、一个证据ZIP和SHA仍需完整。可用时保留精确git原件与固定来源，不能以本分支缺陷断言合并带入或其他分支也存在。

续审或复现时优先定位与入口同批冻结的共享副本并核哈希，不回退到当前安装；冻结布局及路径绑定见共享 `references/delivery-maintenance.md` 的“冻结技能的恢复”。
