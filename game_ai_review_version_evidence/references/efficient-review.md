# 以行为案例驱动覆盖与提速

## 阶段一：准备一次，快速定位

固定两端提交和原始来源，一次建立差异/目标树与原文条款索引，稳定source ID、修订、段落/行和资源坐标，供同组主/次功能发现复用原文定位而不共享候选。同一blob只导出一次：`scripts/git_snapshot.py --help`。批量导出按Git对象ID复用读取与哈希，相同内容优先共用只读硬链接，仍保留基线/目标路径与归属；不支持硬链接时复制已导出的对象，不重新读取Git。快照只用于阅读，隔离实验另建工作副本，不能就地修改共享文件。按需提取资源；同版原文可预导出 `.prefab/.anim/.controller/.overrideController/.meta` 并建GUID索引以减少反复Git调用，均保留原路径与blob校验，不带任何候选推断。未导出不等于不存在；不逐个检查无关贴图/Shader或反复输出巨大diff。缓存不表示已审。

同一来源的抽取与索引按原件哈希及工具版本复用，保留原件和映射；来源或解析规则变化才重建受影响部分。共享准备只提供原文与定位，不预先代判条款效力或传递候选；各角色仍独立回读所用原件。

纯文本用于定位；对拟采用条款，用 `scripts/document_blocks.py DOCUMENT.json --query '规则关键词' --raw --limit 5` 查询原始HTML片段，也支持 `--id` 精确定位。工具保留删除文字标记与原文，忽略图片alt作为规则；仅是定位辅助，仍核效力/适用与冲突。不要直接cat含整篇HTML的长JSON行。非HTML资料沿用其原生读取工具，不为了适配脚本改写输入。

先按真实功能列模块，默认结合固定目标树与有效规范纳入未变更模块，主动检查历史问题；用户限定仅新增时从其限定。形成紧凑条款表：`原文定位/效力 | 实现 | 入口/变体 | 判定 | 证据/缺口`。条款拆到可以判断行为，不把“窗口存在”等同于其中所有功能满足。多阶段规则逐阶段核各自输入、状态和结果，后一阶段已满足不替代前一阶段证明。

## 阶段二：每模块做可核证案例，再判候选

候选可先以紧凑条目保留，再依证据分为确定、条件成立、规范待核或反证排除；不以疑点未闭合提前删除，也不把候选数当Bug数。具体字段及门槛沿用output-contract。

原作者按每个独立结果直接记录 `合法输入及前态 → 操作或事件及分支条件 → 字段/请求变化 → 消费者结果`，附同一触发下的期望、实际和判定证据；共享部分引用窄case ID，不交给合并者从粗父条款重建。局部合同案例另列flow_reachability，不将局部消费者结果写成已发生的玩家反馈。先使用本版配置/合同允许值，后核反例；不能把没有依据的构造数据当局部合法输入或线上可达。案例按实际代码选择，不机械穷举：

- 状态数据：首次初始化与已有缓存、非空变空、连续更新、撤销/反转、互斥状态；核对象替换/字段合并后消费者读到的值，不仅检查写入存在。初次绑定所得边界、排序或显示缓存还要核依赖状态变化后的重算；执行前实时校验不证明显示和选择也已同步。
- 交互选择：用户操作前后显示、内部选择、请求参数与实际执行是否一致；操作取消后继续下一步也属于流程。
- 异步/生命周期：请求拥有者、成功/失败/通知、延迟消费者、重复进入与退出。失败分支还须核状态清理、恢复路径及后续消费者，不停在错误提示或回调名。对每个保护条件写出真假条件与事件来源，不能只看有无handler；区分请求时快照和之后可变状态。
- 独立入口：逐入口核相同能力所需前置数据/检查，首次与缓存路径分开；共享实现只复用同一证明，不假设宿主条件相同。
- 集合与选择：从有效配置取最小例子验证比较优先级、分组、筛选、累积和消费者对象身份；按完整规则手算，不只根据方法名判正确。
- 信息与需求完整性：把有效条款要求的行为和反馈逐项对应实际显示/响应，检查是否被其他组件补全。
- 配置消费链：对影响行为判定的数据，沿本版实际路径核原表/导出、包内默认、下载覆盖或回退、缓存/刷新、解析有效值及最终消费者；只检查实现存在且与断言有关的环节。原表或下载文件有某项，不证明每条加载路径都会采用；无法绑定发布/部署状态时分条件说明，不把未知写成已覆盖或配置未启用。
- 注册/资源载体：从配置枚举不同宿主和路由，核本次启用变体，明确哪些共享证明、哪些有独立绑定。资源参与断言时沿有效引用追子资源、绑定与覆盖到消费者，不能停在主资源存在；只核影响该结果的依赖，不要求遍历全部资产。

阅读量不是覆盖证据。发现缺口先找最可能反证的守卫、公共路径或规则，复用同一证据包及已核公共事实，各消费者仍核独立前态与守卫；被排除项保留短原因，不重复深挖。同根因合并，独立状态缺陷不按同文件强行合并。仅关键静态歧义才做最小隔离执行，保留模拟限制，不为形式重建整个运行环境。

发现有证据支撑的根因后，在本轮仓库/模块边界内，检查共享实现的其他入口、同语义字段的消费者、本版启用的配置变体及相邻状态转换；默认可包含未变更的历史路径，用户限定仅新增时限于变更及影响链。先按实际调用/数据关系定位，再读完整链验证，不能把关键词相似直接当作同类Bug。每个新提出的候选分别核合法触发、守卫、反证及基线归因；同根多处表现合并列影响位置，独立根因单列。不扩展固定版本或允许来源，也不因找到一类问题停止其他功能覆盖。独立发现者只沿自己发现的根因检查；跨角色同类扫描须在约定原稿屏障解除后开展。

同版本原文和已读规则在本轮复用，后续续派只给变更、精确证据游标及必要任务上下文，不重复输出整份技能、整库索引或已闭合长证据。按现有timings记录准备、发现、核证、等待和交付的实际耗时，中断/重启另说明；无记录时不估造净分析时间。优先消除重复读取、空等与重复导出，不以缩减覆盖或弱化反证换取速度。范围、输入、执行条件和验收投入不同的墙钟只作观察，不能推断模型、强度或并发最优；局部脚本基准不代表整轮收益。用户要求冻结后评估时，明确比较全集，分列确定主张正确性、范围内覆盖与等级一致性；待核、范围排除和未核分开，不将采用数或已列条目的一致性称为总体准确率。

## 阶段三：对账、冻结、导出

将条款表与findings按同一触发/结果逐项对账，区分直接违约、依赖阻断与背景。保留原作者细判定；不按父状态、证据并集或finding ID自动填子状态。satisfied/finding均须有对应案例、分支与消费者的原文回读依据；复用本轮已完成的具名核查，漏项/不匹配由具名作者核完后补充，没有案例的已读记录仍待核。代码事实已证而外部影响未证时收窄影响，不因未实测机械降级；不为确认率删除候选。

任务大则分模块/阶段持续推进，保存已核证据与精确下一游标；续审复用同一上下文，不重复准备，不把中间框架冻结为完成。时间/工具真正不足时如实保留未完成，但不能把已有资料未读或推导未完改名输入缺失。完成必要功能路径后收口，不用“绝对穷尽”要求无限检查无关资源。

中间维护JSON与紧凑案例表。渲染前集中核schema、来源引用、固定文件的行号边界、重复根因映射及交接闭合；定位有误先回读原文并留补充，不直接截断行号掩盖错误。语义核清、所需证据整理完后，优先用bundle.py --finalize一次完成同源Markdown、本地/离线HTML和交付包；report.py只用于必要预览或check-only，不把同一终版先反复渲染再反复打包。后续只替换本轮数据并校验，不反复美化页面；模板复用与必要验收按delivery-maintenance执行。节省的展示工作优先投入未覆盖功能、候选反证及非作者核证，不降低证据标准或以拆分同根问题增加数量。结构定位通过不等于语义或实际显示通过。记录准备、核证、实验、导出与等待的实际耗时；仅在输入、模型、覆盖条件可比时谈提速因果。

已授权并发且需高覆盖时按coverage-completion执行同组主/次分区双独立功能发现，在角色上限与复用约束内平衡总负担；原稿屏障前不共享候选/结论。双覆盖属于同一联合样本；独立稳定性样本仍各自完整，不跨样本共享。更新技能后用新鲜上下文复验，旧版/续审不能混计为新样本；发现阶段不提供参考标题、数量、定位、分级或旧探针。评估不能改写冻结原稿，不为通过门槛删除失败样本。

大型任务按 [coverage-completion.md](coverage-completion.md) 收口；已授权并行时由独立协调者分配真实功能分区，分区结果在同一样本内部共享，样本之间隔离。减少单人上下文负担后仍需核边界，不能将团队样本与单人样本的耗时差异归因于技能文本本身。

优先把审查时间用于合法案例、守卫时序和原文反查。原稿、证据、核证各保留一份，使用稳定ID/路径关联；公共证明只记录一次，各消费者保留自己的差异前态与守卫。来源清单、覆盖表、交接和终稿分别引用实际所需内容，不重复抄写整条发现或新增同义账本。独立原稿、反证和判定变更仍须保留，已完成且证据未变的核查直接复用；新证据、冲突、未决项及必需覆盖尚未完成时继续，不因“避免重复”跳过必要工作。协调者复用本轮已具名闭合的核证，重点处理冲突、变更与漏项。完成版在必要交接收口后统一导出；确需阶段交付时标记incomplete，保留open。

派工使用最小绝对路径包：任务根、固定版本、允许来源/索引、输出根及职责边界。运行中用消息补充；已完成且确需继续执行时，用当前工具的显式续派/唤醒能力，普通消息不作为已执行证据。原稿落盘通知给路径、时间、执行状态及下一接收者；纯来源元数据可由协调者回读核实，不为格式重复唤醒。遵守本轮约定的全部独立原稿屏障：各角色职责原稿已含主/次区发现及账本、协调者确认后及时复用Reviewer对账；不得因某一份先保存便提前共享。

联合审查只由协调者生成最终HTML与Markdown。每个职责交付一份JSON，主/次分区分别列紧凑账本，沿用output-contract中的sources、coverage、findings、handoffs、timings字段，不另生成整套网页或重复建报告脚本。证据/发现ID使用职责前缀防冲突；来源定位保持同一固定原路径。补充不覆盖原稿，采用以下结构，并用显式递增序号或依赖确定先后，不能按文件名字典序合并；最终显式记录采用条目及其来源：

- `replacements`与`additions`数组：每项含`section`（sources/coverage/findings/handoffs）、`id`和`entry`（与该section同schema的完整条目）。coverage另附稳定id；新增来源也在此登记。
- `decisions`数组：每项含`section/id/from_status/to_status/reason/evidence_refs`，无原状态用not_present，不适用状态用not_applicable。未替换条目仍保留原判定。
- 计时、完成性等其他补充放`metadata`并说明用途；协调者据具体结果语义合并，沿用原作者细判定并保留采用来源；不同条件/消费者不可仅按ID相邻或证据并集合并，不把分区完成状态直接视为整份完成。

引用只保留足以支撑断言的短片段和精确定位，不把整篇规范、整段资源或重复案例复制到每条发现。初次定位即取相邻原始块核效力，避免最后才重做规则核查。优先深入可能改变判定的缺口及必要覆盖缺口，不能只补已有候选；不能靠多生成格式、多填相似账本或反复哈希证明覆盖。计时把派工错位和显式等待单列，不据单轮墙钟声称提速。


## 耗时记录口径

沿用现有timings，不新增平行性能账本。可取得时记录准备、独立发现、覆盖补漏/核证、交付（渲染/打包）及显式等待的开始/结束时间或实际时长；复用工具/事件时间，无须为计时频繁调用工具。缺记录写unknown，不回推或估造净分析时间。

并行角色时长可以重叠：端到端墙钟按整轮起止计算，不把角色时长相加当墙钟；等待与工作重叠时说明，不直接相减。缺记录的阶段及中断/重启单列。评估速度同时列输入、固定版本、范围、覆盖完成性、模型/强度、并发及实际验收边界；不可比时只报告观察值，不宣称因果提速或最优配置。
