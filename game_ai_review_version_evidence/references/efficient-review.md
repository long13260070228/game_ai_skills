# 执行提速：复用准备，保留独立发现与核证

本文件负责准备、调度和复用；判定见decision-rules，覆盖/独立原稿屏障/交叉核证/停止条件统一见coverage-completion，字段见output-contract。用户范围优先；减少重复I/O、记账和复核，不用缩小覆盖、删候选或降低门槛换取速度。

## 1. 准备一次即可派工

固定输入和目标/基线后，按真实功能、入口与规范列模块和职责。默认包含授权范围内未变更历史模块；仅新增任务限定在差异和影响链。先登记各范围的模块归属、关键分区及具体排除依据；实现相同只说明归因，不能自动推出本轮无需审查。目录级索引足够启动，后续解析按需补充，避免全组等待完整准备。

复用依据为原件哈希、固定版本及解析工具版本：

- 同一Git blob只导出和哈希一次；用 `scripts/git_snapshot.py --help` 批量读取。可复用只读硬链接，不支持时复制已导出对象，保留每个目标/基线路径及归属。实验另建副本，不修改共享源。
- 同版文档只解析一次，保存原件、段落/原始块及映射；配置、资源引用/GUID等索引按实际断言按需生成，不全量扫描无关资产。版本、文件或解析规则变化，仅重建受影响缓存。
- 共享准备只含原文和定位，不含条款效力判断、候选、探针答案或结论。每个独立发现者回读其所用原件；缓存存在不等于已审。
- 纯文本用于定位。HTML原件可用 `scripts/document_blocks.py DOCUMENT.json --query '规则关键词' --raw --limit 5` 或 `--id` 查看相邻原始块；核删除/修订和效力，不用图片alt代替规则。其他格式使用原生读取，不为适配工具改写输入，不输出整篇长HTML行。

## 2. 按负担分区，不重复准备

大型且已授权高覆盖审查，关键分区仍由两位角色分别完整读取必要规范、实现、配置和消费者，保存独立原稿。两者可分别优先规范轴和实现轴，但各自均须闭合两轴；横向补漏不代替第二份功能发现。按真实工作量而非文件数分配主/次区，人员和配置服从授权，不为了凑组用满并发。

派工只给绝对路径包：固定版本、允许原件/索引、输出根、职责和必要规则引用。入口及当前阶段规则读一次；专项参考按需读取，不在每次续派重复整份技能、全库索引和长案例。续派复用适配上下文并给精确证据游标；已接触旧结论的角色不能恢复为独立发现者。

全部约定独立原稿冻结前只交流来源、版本及范围纠错，不共享候选或公共推断。先完成者可在既定职责内补未覆盖条款和边界，不空等、不提前读取其他原稿。关键依赖阻断保留handoff与游标，继续不依赖它的工作；这不授权拆掉原稿屏障。屏障后再复用已完成角色核证，不把已见结论的检查称第二次独立发现。

## 3. 案例紧凑，证据完整

原作者沿用现有条款/案例行记录：`合法前态及输入 → 操作/事件与分支 → 字段/请求变化 → 消费者结果`，附同期望、实际、原文定位及反证。复合结果分别判定，公共部分引用窄case ID，不交给合并者从粗父条款重建。共享证明只覆盖其实际触发和结果，差异前态与守卫仍各自核证。

按实际实现选择能区分行为的有限案例，不机械穷举：

- 状态与交互：初始化/缓存、非空变空、连续更新、取消后继续、选择和实际请求是否一致；核依赖变化后的显示/选择重算，最终执行校验不代表前面状态正确。
- 异步与生命周期：发起者、所有者、成功/失败/通知、退出、延迟消费者；区分请求快照和后续可变状态。核守卫真假条件、注册及覆盖时段，不停在回调名或错误提示。
- 入口与集合：不同宿主/入口各自数据准备和守卫；用本版有效配置检查对象身份、排序、筛选、边界及实际消费者，不只看字段非空或方法名。
- 规范与载体：每个有效行为、文字及反馈分别核；沿实际配置原表/导出、包内/远端/回退、解析和消费者检查适用环节。资源参与断言时沿引用、嵌套覆盖和绑定追到生效对象，不止于资源存在。

局部合法边界和完整玩家流程按decision-rules分别证明，未观测线上频率不自动否定闭合静态链。只对影响判定的静态歧义做最小隔离实验，保留输入、命令、输出、模拟及环境限制，不为形式重建整个运行环境。

自己发现根因后，在本轮范围内按实际调用/数据关系检查同类入口、字段和状态；每个候选独立核合法触发、守卫及归因。同根合并，独立状态缺陷不按同文件合并；不能用这一类扫描替代其他功能覆盖。跨角色扫描须先满足原稿屏障。

## 4. 核证一次，按变化补核

全部原稿冻结后，每个确定项（含新增/升级项）指定具名非作者，先找足以推翻断言的反证，再独立核正面证明。交接关联同一ID、窄断言、核查人、证据及结论；具体门槛沿用coverage-completion，不能只认可摘要或以没有反驳当作成立。单人及非作者条件遵守本轮授权。

已完成且来源、合法触发、规则、根因、影响和证据未变的具名核查直接复用。协调者检查范围、冲突、去重和关键边界，不重新完整核每条；断言/前提改变、有新反证、证据过期、可读缺口未闭合或必要覆盖未完时，由对应职责补核受影响部分，不重新分派整个模块。复用不能代替约定的第二份独立原稿或确定项非作者核证。

复核问题之外，按coverage-completion检查未覆盖条款以及已标satisfied/out_of_scope的高风险行。原件已提供但尚未读取/推导的，继续并记open；只有真实缺源才记blocked及具体缺口。不要把历史归因、载体类型或另一条安全路径自动当排除理由。

每个职责只维护一份原稿JSON，发现、覆盖及证据以稳定ID关联。补充不覆盖原稿，以显式序号/依赖确定次序，不按文件名字典序合并：

- `replacements`/`additions`：`section/id/entry`，entry沿用对应sources、coverage、findings、handoffs schema；coverage需稳定ID。
- `decisions`：`section/id/from_status/to_status/reason/evidence_refs`；无旧状态用not_present，不适用用not_applicable，未替换项保留原判定。
- 时间、完成性等放metadata；最终adoption_trace关联实际采用来源。不同条件/消费者不按证据并集自动合并，不用分区completed代替整体完成。

## 5. 一次导出，按证据验收

语义收口后集中核schema、来源、行号边界、去重及交接，再用现有 `bundle.py --finalize` 一次生成同源Markdown/HTML/ZIP；report.py仅用于必要预览或check-only。不由各角色生成网页，不新增报告脚本或反复美化。计数、定位、链接、包内入口与包完整性仍须校验；模板复用边界见delivery-maintenance。

只有语义/引用/包发生实际修改或出现失败才补验受影响检查；没有新风险不重复全量渲染、哈希或验收。结构通过不代表语义/运行通过。必需工作未完继续；真实受阻则incomplete，不把已存在材料没查完包装成缺源，也不以绝对穷尽为停止门槛。

沿用timings记录准备、发现、核证/补漏、等待、交付及整轮起止；复用事件/工具时间，缺失写unknown，不频繁专门取时、不回推净分析。并行阶段可重叠，不相加当墙钟，也不直接扣减重叠等待。

本版效果尚须独立复验：旧/新版使用相同输入、固定版本、范围、模型/强度与并发配置，分别冻结后评估有效去重根因、待证项、等级、必要覆盖及墙钟；另用未见过的项目或版本复验。真实规范冲突与尚未做完分开，不能为提高确认率删除候选。不给发现者旧标题、定位、数量、等级或探针；复验不回写独立原稿。一轮结果只能说明该样本，不承诺固定节省比例或跨项目稳定优势。
