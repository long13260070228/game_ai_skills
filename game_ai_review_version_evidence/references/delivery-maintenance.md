# 轮次、成果维护与交付

适用于初次交付和用户要求的本轮成果自审、展示调整、重新打包。发现阶段仍遵守独立性规则；本文件不授权读取外部旧报告、参考答案、Bug清单、服务端实现或后续版本。

## 轮次与停止

默认1轮独立发现，完成覆盖补漏与必要核证，最后一次终稿核对；取消固定三轮文档自审。用户当次明确指定轮数时从其要求。按实际缺口补核，依据 [coverage-completion.md](coverage-completion.md) 的停止条件完成必要核证、覆盖收口、终稿核对、冻结和交付；必需工作尚未完成须继续，受阻则如实标记incomplete，真实证据不足才单列待核。已做过的方案自审不自动成为后续任务的固定额外轮次。

交付后的明确新请求可启动本轮成果的续核、文档自审或展示维护；记录阶段及授权，不把已见本轮结论的上下文称为新的独立发现。维护可读取本轮自身报告与原稿，不能借机读取原先禁止的旧答案或扩大版本。用户仅要求展示或打包时，不重判事实、等级或归因。

审查中逐项核证合法触发、实际行为、反证、严重度和新增归因；回到未覆盖的原始条款、入口、异步时序及配置变体补漏。已有原稿、核证和覆盖账本直接复用，不为凑轮次另写重复记录。终稿集中核对表述边界及数据/引用一致性，记录实际改动和遗留项；计数、链接和包完整性尽量用现有脚本检查。终稿核对不能替代默认要求的非作者核证。

## 范围核对

交付时明确回答是否扩大范围，依据包括：原请求与实际固定的基线/目标提交、允许输入及其补充、已核模块、同版依赖补读、隔离实验和排除接触。读取同一固定版本的未变更依赖是核证需要，不自动等于扩大新增问题范围；新增输入或实验的种类、用途和授权须单列。

默认允许主动审查给定仓库/模块中目标版本仍存在的历史问题，交付写明历史模块的实际覆盖及缺口。基线用于逐项归因，不因允许历史审查而读取更多提交或旧缺陷结论；历史确定项采用与新增相同的核证标准，计入确定总数及历史分类，不计入新增数量。用户当次明确限定仅新增时优先执行。

仅报两提交间引入的问题时，每项新增归因仍需基线同场景、需求变化或迁移条件的具体证据；历史与归因未知单列，不能进入新增Bug数量。不能凭范围摘要替代逐项归因，也不能把全部确定问题数称为新增Bug数。范围有实际变更或证据不足时具体写明，不笼统保证“没有扩大”。

可在review_history/附加账本记录scope_audit，保留原始输入可用性、实际读取状态和包内附件状态三者的区别；原件未装入用户另行指定的轻量包不等于审查时未收到。

## 验收与完成声明

分别记录结构校验、数量/筛选交互验证、来源与相对链接检查、网页视觉验收和真实运行/集成验证。每项写实际执行方式、结果和限制；未执行、受阻与失败分别说明，不用脚本通过替代视觉验收，不用静态核证冒充实服复现。

报告必要语义审查的review_state与展示/运行验收状态分开，未做运行验证本身不自动否定已闭合的静态证据。网页验收按下述模板复用规则确定范围；无法执行的本轮必要检查保留准确原因，不宣称全部验收通过。

## 定稿模板复用与投入优先级

用户更关注有效问题的质量与数量。主要时间用于独立发现、未覆盖行为、合法触发、反证、归因及非作者核证；不设问题数配额，不以反复润色页面、增加交付格式或重复自审替代这些工作。终稿只做一次必要核对，不自动触发页面改版。

当前已定稿且通过视觉验证的report.py模板作为默认展示入口。后续审查通过同源review.json更新本轮数据，复用渲染器和bundle.py，不手工复制旧项目结论、不读取旧报告来引导发现，不为每轮新建页面、脚本或重做排版。仅用户明确要求调整、发现实际展示缺陷，或新数据/功能超出既有模板承载能力时修改模板；事实审查中的UI/资源与交互缺陷核查不受此限制。

- 模板与渲染器未变且已有适用的视觉验证时，记录所用渲染器哈希及既有验证位置/范围，复用该验证。每轮仍核本轮数据结构、三种格式的事实/计数一致性、统计与筛选同步、来源与相对链接、证据包完整性及解压后的离线入口；这些检查不因模板稳定而省略。
- 日常数据替换不默认重做完整桌面/移动端截图验收，不追加美化轮次。新内容存在明确显示风险时，针对长文本、哈希、表格等相关区域做必要抽查；没有适用的既有验证、模板/渲染器发生展示行为变化、实际显示异常或用户要求时，再打开实际HTML做相应视觉与交互验收。完整布局改版应覆盖桌面与窄屏。
- 验收记录清楚区分“本轮实际验证”“复用既有模板验证”“本轮未执行/受阻”。既有视觉验证不证明本轮数据与链接正确，也不能写成本轮截图验收通过。后续模板修订单独留版本与验证证据，稳定后继续复用。

## 唯一终版与修订追踪

每次交付指定唯一推荐入口与同源JSON。原始分区、冻结结果及历史修订保留，放入清楚标记的审计区域，不让多个同名报告竞争“终版”。

发现阶段的skill_version、输入与原稿冻结后保留。后续展示/打包修改使用presentation_revision；事实续核在review_history中另记授权、原/新判定、证据和采用理由，保留旧快照，不倒填为原始独立发现。附加维护字段由既有渲染器完整保留，无须为维护重置分类schema。

技能内容变化时保留修订前快照，并以版本号及内容哈希标识实际使用的发现/维护技能；同一标称版本的快照内容有差异时不能靠版本名声称相同。对已交付报告，不为更新技能而重写其发现版本或假装重做审查。

报告、附件或包内说明变化后，重新生成相应文件清单、ZIP及SHA-256；同一终版的网页、JSON、Markdown和下载包应指向同一修订。仅修改未来使用的skill而未改本轮报告/附件，不要求改写历史交付包；说明本次修改边界即可。

## 网页入口与证据包

默认一个证据ZIP，`index.html`为唯一推荐阅读入口，JSON/Markdown为辅助入口，不默认另外生成阅读ZIP。网页按读者任务排列：标题与版本摘要 → 简短结论和统计 → 证据包下载 → 问题总览与筛选 → 问题详情 → 资料与审计折叠区。摘要只能提炼已有事实和验证边界，不新增发布结论。

- 总览表与详情均从同一findings生成，编号可定位详情；搜索、等级、归因及模块筛选同步作用于总览与详情。新报告每项登记module；维护旧报告缺字段时，按原稿、覆盖账本及引用路径核实并补齐标签，记录依据，不改断言或归因。渲染只采用已登记module，仍无法确认时显示未分类，不凭标题猜测。证明方式保留原文，区分静态、隔离执行与真实运行的已记录边界，不从成功日志自动升级验证状态。
- 目标/基线各占一行，显示固定来源对应的分支名及完整SHA，不缩略或用当前Git引用代替历史冻结来源。正文默认16px，表格与辅助说明不小于14px，文字使用清晰对比度；完整哈希可换行，下载元数据使用可用宽度，不能被网格自动放入窄标题列。
- 顶部下载区只提供一个证据包，显示用途、实测大小、SHA-256与校验文件，并在页内导航提供证据包直达入口。未打包或缺少校验文件链接等完整元数据时明确未就绪，不显示下载按钮，也不声称包内材料已齐备。完整输入、严重度标准、来源、覆盖、审计和长证据后置折叠，保留锚点导航；免责声明保留简短摘要，详细边界按需展开。
- 证据包包含四项终版报告、所用需求/配表、引用和核证必需的固定版本源码/资源与实验材料、原始分区、交叉核证、自审、覆盖与冻结账本、实际技能快照。证据选取同时核查local_copy及无链接的来源定位/原稿引用，不能只看网页链接就误删必要材料。不存在的基线文件以固定树/命令及结果证明，不伪造空文件。包内index.html可离线阅读，并说明证据已包含，不指向外部自身ZIP。
- 用户另要求轻量阅读包或完整工作存档时才单独提供，明确含/不含原件及适用范围，缺件链接须转为说明，不冒充可离线核证的证据包。

先将review.json、data-sources.md和所需材料整理到交付目录，最终交付推荐 `scripts/bundle.py DIRECTORY --zip OUTSIDE/evidence.zip --finalize`：从同一JSON生成Markdown及两种HTML，再生成归档和校验，不改写事实JSON。单独预览继续使用report.py；已冻结且需保留原Markdown的重打包使用不带--finalize的原命令，并使用该成果冻结的渲染器。bundle复用report.py，生成单一证据ZIP、MANIFEST.json逐文件大小/哈希、整体SHA-256校验文件、delivery.json展示清单，并更新目录中的index.html下载区。delivery.json仅为包信息，不是审查事实源。打包器排除packages、cache、.git、Python缓存及旧交付清单；必要缓存证据须先整理到evidence/audit，不能依赖默认排除目录。软链接须先按版本归属整理为普通文件，否则停止打包。

本地网页用生成的交付清单展示外部ZIP的大小/哈希；ZIP内网页用package展示形态，两者共用同一review.json。整体ZIP哈希只写到ZIP外，包内MANIFEST.json不含自身哈希，避免自引用。包内与本地网页仅下载区因交付形态不同。

打包前检查主要体积来源。相同依赖保留一份，按共享目录调整包内相对路径；不能将绝对软链接展开成多份整库快照。基线与目标的不同内容不得为去重相互覆盖；内容相同需保持版本归属可核。排除可再生缓存与无关文件，不以体积目标截断证据或悄悄删必要附件。体积仍主要由必要原件构成时列出来源，不把本次样本大小固化为通用硬阈值。

包内附入口说明、含/不含材料的边界、逐文件大小与SHA-256清单；清单自身不作递归自哈希。ZIP与其整体SHA-256放在源目录之外，不递归包含自身。打包与回读采用分块处理；一次完整回读同时核每个归档条目的CRC、大小与SHA，另核清单与条目集合一致及整体ZIP哈希，不以采样代替完整性校验。相同HTML目标的锚点解析仅在同一次链接检查中复用，仍逐个检查链接和锚点；跨次检查不复用可能失效的解析缓存。逐项验证归档条目、文件校验值、ZIP完整性及报告相对链接；证据包另核必要原件存在及解压后的离线入口。报告结论或附件没有变化时，不借重新打包重判问题。

## 最终回复

说明本轮完成性及实际轮数；给出确定问题数、待确认数、P0～P4分布与新增/历史/归因未知口径，明确范围是否变化、未完成验证和主要覆盖缺口。提供唯一推荐HTML入口、一个证据ZIP链接、实测大小及SHA-256校验文件。事实未变的展示或打包维护只说明相应变化，不将维护称为新一轮独立审查。必要审查或验收尚未完成时明确指出，不能只凭已生成文件宣布全部完成。
