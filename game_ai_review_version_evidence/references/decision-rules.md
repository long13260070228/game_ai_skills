# 判定与归因决策规则

## 事实与条件

先固定所述窄断言，再分开核代码事实、规则效力、局部输入合法性和玩家流程可达性。固定合法输入下的必然违约可由静态反例证明，不要求线上已经发生。

- `local_contract`：先以已有方法/接口固定完整局部边界，说明输入/前态、有效合同或明确程序不变量、边界内必经前置与最终消费者。`local_input_basis`须核缺失/缺省、值域、组合、完整身份及调用前提；C#类型可表示某值不等于业务合法。不能从同一方法中段开始，省略必需字段或跳过局部守卫，也不能凭任意模型、构造数据或假想正常缓存确认。边界外生产路径是否已在本版成功构建该前态另属flow；已有独立合法域证据时，不额外要求有Bug上游实际构建成功。缺少独立合法域依据时，写清所缺语义，不能以边界名称代替证明。
- `user_flow`：从固定实现的实际玩家入口，按本版合法合同/配置条件核资源、完整守卫、时序及消费者到结果；可静态闭合，不要求先观察一次生产执行。confirmed须该链闭合且`flow_reachability.state=reachable`；实际部署和线上发生仍只按已有观测陈述。

`status`表达所选断言的确定性。局部证据闭合时，即使流程被另一confirmed项阻断或尚未证明可达，仍可记local_contract+confirmed并计Bug；流程另填blocked_by_confirmed_issue或unproved，影响限于局部违约，不声称真实玩家影响、频率或资产后果已证。规则或局部输入合法性未证，不能借可达性分离升级confirmed。

## 主状态

按主要未决原因归类，可附 `status_basis` 与 `unresolved_dimensions`，避免一枚状态覆盖全部事实：

1. 明确反证排除该条最窄缺陷断言：refuted，并标明被排除的断言。若只反证扩大影响或附带条件，收窄该表述并保留其他已证实现事实，主状态按剩余最窄缺陷重新判定，不将整条自动判假。未复现不是反证。
2. 本版真实配置未启用相应分支/能力：inactive_config，并令flow_reachability.state=inactive_config；不计确定Bug。单纯被另一Bug阻断不是配置未启用，也不是缺输入。
3. 实现事实明确，预期条款效力、适用性或冲突未解决：requirement_unverified。
4. 规则有效，但所述断言所需的局部输入形态/组合/调用前提，或user_flow的必要可达条件缺证：conditional；只缺local_contract的流程可达性时，不能据此降其局部确定性。
5. 实现、有效规则/不变量、合法输入与相应守卫、消费者均闭合：local_contract可confirmed；user_flow还须完整流程可达。仍标注是否仅静态证明。
6. 连实现事实或根因也不明确：unresolved。

若多个维度同时不足，主要状态不能隐去其他不足。不得把所有依赖用户操作/异步时间的静态结论自动归conditional，也不得因为能模拟出错就自动confirmed。

flow_reachability独立判定：reachable须有本版合法合同/配置条件下从实际入口到结果的完整链，可由静态证据证明；blocked_by_confirmed_issue须引用本样本另一条confirmed ID及阻断顺序/证据，不得引用自身或conditional；unproved须指出哪条必要条件、守卫、资源、时序或外部语义未证，不假定所有路径均受阻。把静态合同条件可达、实际部署观测、生产发生频率分开写；未运行客户端、未取得实服编码或发生记录本身不自动成为unproved依据。若未知外部行为确会改变所述结果，只保留那一具体依赖。未知实际编码/频率不抹去合同允许输入；客户端接受某编码也不证明合同允许它。字段结构不变，见output-contract。

同根只保留一个发现ID与一个claim_scope；局部与用户流程断言互斥计数。后来证明完整流程时可显式更新同项范围与影响，不另增重复Bug。被阻断、可达未证均是确定项中的流程子计数。严重度仍按已证影响独立判断；静态可支持高级别，未实测不自动限P；P0/P1仍须对应严重后果、合法触发、范围与恢复限制证据，局部下游风险不继承阻断者等级。恢复/绕过只能采用已核的自动恢复或正常用户操作完整链；离开页面不等于能力恢复，重进须核不会重复同一失败。改输入/对端编码、开发修复或未证可触发的内部重建机制，不算正常用户绕过。

客户端自身状态或生命周期不变量、以及有效合同下合法输入必然导致的本地违约，可在证明完整时静态确认，不以取得服务端源码或 Bug 列表为前提。合同已允许的输入形态可作为静态条件，不因缺真实回包自动待核；声称某部署已经返回该形态或某现实后果已发生，则须相应观测。合同未规定、却对所述结果必需的对端行为（如额外推送、是否接受请求或发奖）未获证明时，仅将该具体依赖维持待核。服务端设计可证明合同，不等于部署事实；已证本地错误也不扩大为对端失败或资产损失。

## 规则效力

允许来源的有效正文及用户指定的同版规则可作为审查规范，不机械索取额外审批。允许读取、原文未删除、适用于本次目标分别核对。补充条款可能细化正文，也可能与正文矛盾；查适用条件和可证明的层级/时间关系，不能一律把“补充”当作覆盖，也不能只因表面用词不同就判冲突。无法消解时保留冲突证据。纯文本丢失格式时不推断原条款仍有效。

## 主归因

先问“与基线相比，什么变化使此行为成为当前缺陷”：旧流程迁移到新入口/宿主/数据合同缺适配，主归migration_gap；既有行为遇本次新规则才不满足，主归new_requirement；本次实现引入错误转换/状态或算法，主归new_implementation；基线同场景已存在且规则未改变，主归historical。多因素可附次标签，主归因选择解释最直接根因的一项并给证据。仅文件新增或类名替换不能证明归因；无法核实则unknown。

当本次明确新增的用户能力整体缺失时，可主归new_requirement；该能力已有实现而其内部状态/算法违约，通常主归new_implementation。复用/迁移引入的新入口或合同缺口优先说明migration_gap。归因不是错误程度，也不是对开发者责任的推断。 对已核证“基线旧实现 × 本次新配置”导致的新场景违约，保持主归因migration_gap，另填origin_subtype=legacy_code_new_config供首页单列；给出基线同场景行为、固定配置差异及实际消费者的触发因果。仅旧代码遇新入口/宿主/合同的其他迁移不填此子类，不能因都属于migration_gap混算。


## 防止只看局部的判定

对拟采用的规则，先并列同批正文、补充和接口中关于同一行为与条件的原文，再判断是细化、可兼容还是冲突。不能只读最先命中的句子，也不能因为某份资料名为“接口”或“补充”就自动覆盖其余规则。结合正文、标题及相邻条款判断适用范围，不因章节摆放自行添加原文未表达的入口或等级限制；同条件和结果存在不能消解的不兼容要求时才保留冲突，不选能制造缺陷的一方。

配置证明实际取值与可达性，不自动证明需求正确或取代规范；需求声明某能力也不证明当前配置启用了它。分开核证。对“未实现/未刷新”断言，必须检查公共包装、中间分发、事件通知、外部消费者和资源绑定，不能因当前方法没有相应语句就下结论。


待核命题的细分与收口见 [coverage-completion.md](coverage-completion.md)。需求精确格式或数据形态未核，不能自动否定同批有效来源已经证明的更窄能力；没有有效最小要求仍保留待核。

## 对待核理由本身举证

“规则未提供”和“尚未找到规则”不是同一判断。拟标requirement_unverified时，记录已经反查的原始正文、相邻段落、图示及补充；若同批有效来源能证明较窄能力，按该能力判定，不要求在另一份缺失文档中重复出现。静态示意只证明其实际表达的内容，不代替动态规范。代码自身明确建立的状态一致性也可作为不变量，但应给出产生者、消费者和相互矛盾的具体状态，不能用主观偏好代替规范。

以另一处异常限制候选时，先标它位于所选局部边界之内还是之外，再写精确调用、输入类型、转换/重载、执行顺序、异常前保留状态及catch后控制流。边界内必经异常不能跳过；边界外构建失败可阻断flow，却不否定已由独立合同/不变量证明的合法局部前态。若改变断言边界须显式记录并重新核完整前置，不能用改名截断同方法或假设修复。同为某种字段声明类型，不代表走相同转换；一次初始化失败，不代表先前状态被回滚或所有局部更新都不可达。若所选流程被阻断，检查其他实际入口与保留状态，分别判定局部合法输入下的消费者行为及flow_reachability；不以玩家链未闭合否定已闭合的局部合同断言。既不假定上游永远正常，也不以一种典型失败断言所有路径不可能。相关结论经过转换、桥接或解释边界时，核实际调用及本版可读绑定。普通语言语义可按其适用标准和已核实现推导；只有证据表明相关路径经过可能改变该语义的自定义边界，且该差异会改变结论时，才把未核语义列为具体缺口。不同执行模型的实验只证明所用模型，不因假想差异自动降待核，也不假定自定义边界消除异常。

确需外部编码、响应或状态才能证明的条件，应明确该条件及允许来源为什么不足。客户端接受某编码不自动证明对端会发送，合同也不能被任意补成更宽或更窄；不要为保留结论编造输入，不要为排除结论添加原合同没有的禁止条件。静态可达、实际部署可达与生产发生频率分开陈述。


声明缺少来源前，先核同批原生元数据与对应原文；来源未定位不等于未收到。待核项按output-contract的proof_gaps仅列真实缺失、来源冲突或必要检查未完，附最小下一步，不重复整套事实账本。
