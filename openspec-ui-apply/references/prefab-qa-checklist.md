# Prefab 验收清单

在 `ui-validation.md` 中按页面记录下表。结果只能为通过、失败、未执行、不适用；后两项必须说明原因。检查需要 Unity 保存后的资产及真实截图，而不只是生成工具代码。

| 检查 | 证据要求 |
| --- | --- |
| 保存、导入、重载 | Unity 版本、执行入口、日志、Prefab 路径和重新加载结果 |
| 节点与组件 | 对照 ui-contract 的必需路径/组件检查，包含非激活状态节点 |
| 引用完整性 | Missing Script、损坏引用、嵌套 Prefab、Sprite、材质、字体及 Editor-only 依赖结果 |
| 动态资源可达 | 根据当前收集规则与加载入口核对页面、Item、图集/Sprite 名称 |
| 默认显示 | 默认 active、选中页签、列表模板隐藏/激活行为 |
| 交互 | Button 点击区域、遮挡/穿透、ScrollRect、关闭窗口、需求中的状态切换 |
| 分辨率与安全区 | 契约指定尺寸和代表性长宽比的截图，安全区未被重复应用 |
| 视觉 | 实际打开截图核对设计图：层级、边距、字体、缺字、色彩、九宫格、裁剪、对齐 |
| 边界文案与列表 | 长文本、大数字、空列表、多个 Item；仅覆盖需求适用状态 |
| 真实窗口入口 | 通过 UtilsWindow/目标入口运行；预览截图不能替代该项 |
| 再次执行 | 更新工具复跑后无重复节点/组件，已有 GUID 和人工编辑保留 |
| 工作区差异 | 变动仅覆盖本次页面与资源，相关 `.meta` 完整，未更改其他模块 |

没有提供适用状态的设计时，注明依据或缺口；不为凑齐表格制造产品需求。
自动化结构检查通过与人工/视觉验收通过分别记录。不能仅凭 CLI `isComplete`、tasks checkbox 或图片生成成功证明 UI 完成。
