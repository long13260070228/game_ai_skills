# P0～P4 通用严重度

这里的 P 表示缺陷影响与处理优先级，不表示证明强度。先确定最窄已证后果，再结合触发范围、恢复方式及功能重要性分级；默认采用下表通用规则；用户明确指定项目分级时记录该口径并采用。仅材料自带P标签不等于用户指定，不直接沿用。静态证明可以支持高级别，但必须闭合相同的证据链。

| 等级 | 判定规则 | 边界 |
|---|---|---|
| P0 紧急 | 已证可达路径造成系统或核心服务整体不可用、大范围不可恢复的数据/资产破坏、严重安全边界失守，且缺少可用的正常恢复或遏制措施 | 需要后果、范围、不可恢复/无法遏制证据；不能把可能崩溃、单页异常、未证对端损失写成P0 |
| P1 高 | 核心流程在合法常见场景被阻断，或发生实质性错误交易/数据破坏/权限风险；正常操作不能合理绕过，影响足以阻塞该核心能力交付 | 核心性、触发和不能合理绕过分别给证据；仅影响展示、可重新进入恢复、需要未证响应的后果通常不足以支持P1 |
| P2 中 | 具体功能、状态、结果或有效需求明显违约，有实际用户影响；局限于特定流程/条件，尚未证明达到P0/P1，或存在正常恢复/绕过 | 功能遗漏可以是P2，不因叫“新需求”自动降低；有绕过不自动变P3 |
| P3 低 | 局部反馈、提示、非关键交互或信息不一致，功能主体仍可完成，影响有限且可恢复 | 若文案会改变重要决策，应按实际后果重新判断，不能一律P3 |
| P4 轻微 | 有明确标准的细小视觉/文字/一致性偏差，几乎不影响操作或结果 | 纯审美、风格偏好、重构建议不是确定Bug；标 `finding_kind: improvement` 并排除确定Bug计数。用户忽略样式时记录为范围外，不凑数 |

## 必填依据

每项 `severity_basis` 包含：

- `consequence`：本次证据已证明的后果，与 impact 一致。
- `affected_scope`：受影响流程/对象；未知频率写未知，不编造用户占比。
- `trigger_basis`：合法触发及其证据引用。
- `recovery`：已检查的自动恢复、重新进入、重试、回退或其他正常路径；无法判断写明限制。
- `rationale`：为何满足所选等级及未升高的具体依据。
- `evidence_refs`：支撑上述判断的本项证据定位或ID，不能只填抽象风险名称。

未闭合候选仍可按已证本地影响填暂定P等级，明确暂定理由；严重外部后果仅写 `potential_severity` 和所缺证据，不混入已证 impact。若连本地影响也未知，明确标注等级暂定，不能由P标签倒推出confirmed。

## P0/P1检查与验收

冻结前单列所有P0/P1，回读从入口到后果的完整路径、保护/恢复措施、固定配置和基线归因，检查后果是否超出证据。另沿本轮范围内核心流程核对可用性、交易/持久状态与权限边界，记录覆盖和缺口。高级别为空时只写“本次未发现已证P0/P1”，不能宣称绝无严重缺陷。

发现阶段按证据独立分级。评估阶段可以标注误分级、已证严重项漏报和未覆盖项，但不得修改冻结原始结果或以“P0/P1为零”作为通过捷径。没有真实严重性真值集时，验收结论限于已核证范围。

## 报告展示口径

首页P0～P4分布只统计确定问题，合计等于确定问题总数。待确认是确定性分组，不是P等级；详情中的暂定P等级不混入确定问题分布。已反证、配置未启用及改进建议归入独立审计记录。局部已确定但流程未证/受阻的条目仍按已证局部影响分级，流程状态单列。

报告须展示本文件的五级判定表和边界；筛选标签同时显示代码与名称（如P2 中），不能仅显示“中”使用户难以对应P级。
