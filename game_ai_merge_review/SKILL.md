# 分支合并引入问题审查

先固定源分支、合入目标分支及完整SHA；明示方向“源 → 目标”，不能把合入目标当成被审源实现。MR按共享 `references/mr-intake.md` 确定源head、差异基点和MR目标分支快照；记录来源、diff版本与比较口径，不能将merge-base冒充目标分支头。

审查本次合入目标分支**引起**的缺陷：源分支变更、新需求遗漏、源变更与目标已有实现/配置交互、合并结果差异。基线已有同场景同规则问题不是本次引入；作为依赖或阻断可记录证据，不计入本次新增。允许补读未改动依赖及基线以核证，不自动扩大为独立历史审查。每个确定新增必须有明确触发、目标基线事实、源变化/整合因果及反证；无法证明新旧归因记 `unknown` 待核，不能冒充确定新增。

默认审查实际可证的合并结果或在隔离临时对象/副本生成的等价合并树；源diff、merge-base、源head与目标head分别记录，目标独有改动本身不得归给源分支。合并冲突或不能取得必要对象时不修改原仓库、不虚构成功合并；记录缺口并标记相应结论及总体完成性。若用户只要求审源分支diff，按其范围执行，但不声称已验证最终合并交互。已合并MR仍按指定冻结版本，不自动取当前主干。

报告 `review_kind: merge`；`target` 为本轮被审源head或明确实际合并提交SHA，`baseline` 默认为冻结合入目标快照，`comparison_kind: target_head`；仅用户限定源diff时用 `mr_diff_base`，其他显式比较口径如实登记。单列源/目标head、merge-base、合并树ID及是否验证合并树；树ID不能冒充提交SHA，源相对基点变化不能直接证明合入新增。用户明确SHA或比较范围优先。只在隔离目录只读获取Git对象，不切换/合并用户工作区。

读取并遵守共享工作流 `${CODEX_HOME:-$HOME/.codex}/skills/game_ai_review_shared/WORKFLOW.md` 和适用参考；本入口范围优先于通用表述。冻结入口skill及共享工作流/工具的实际内容及哈希；独立发现、反证、严重度、非作者核证和证据边界不降低。使用共享 `scripts/report.py` 和 `scripts/bundle.py` 交付HTML、JSON、Markdown、来源清单、一个证据ZIP及SHA。

续审或复现时优先定位与入口同批冻结的共享副本并核哈希，不回退到当前安装；冻结布局及路径绑定见共享 `references/delivery-maintenance.md` 的“冻结技能的恢复”。
