# project_migrate 完整链路与功能边界

依据 tools_h5 的实际入口和调用方审查，核对日期：2026-10-10。维护工具或审查完整流程时读取本文件，并重新核对当前源码；不能仅凭这份列表判断新版本已经实现。

入口：build.xml 的 project_migrate → src/migrate/migrateProject.py；默认规则由 clientConfig.py、platformRules.py、storageRules.py、templateRules.py、atlasRules.py 执行；内部清单、安装格式化及提交由 internalAdaptation.py、migrationAdaptation.py、projectConfig.py 执行；源码快照和分支由 migrationGit.py 执行。

## 功能列表

每行一项功能；“清单”表示 skill 必须根据实际项目准备内部数据，不是无准备的默认映射。

- 统一入口：Ant 将输入传给 Python，失败向 Ant 传播，不依赖 init、tools_update 或构建任务。
- 输入校验：核对源仓库、源分支、目标仓库、产品版本及 init 所需 USER_NAME，版本原值不补齐。
- 仓库保护：要求空目标远端及未初始化的本地目标，tools_h5 使用 master；新增配置时只因工作区已有目标条目而拒绝配置覆盖，不因已有暂存／未暂存改动拦截。使用临时提交索引隔离目标条目，保留其它文件与配置条目的暂存／未暂存内容；特殊索引状态、进行中的 Git 合并／变基等操作、执行期间并发变化仍停止。提交期间发现配置变化时保留用户文件及已生成提交并明确报告，不覆盖用户保存。继续已有目标适配仍要求 projects.json 无用户改动。
- 来源固定：查询指定源分支最新完整 SHA，浅克隆该分支并核对 SHA，源分支漂移时停止。
- 快照复制：只删除临时源副本根 .git，复制全部其余内容及隐藏项，核对内容、模式和符号链接，不导入源历史。
- 未支持源码拦截：遇到子模块或未下载 LFS 指针停止，不将不完整快照报告成功。
- 版本基线：创建 develop_版本号 的唯一无父初次提交，标题记录源项目、分支、短 SHA，正文保留完整来源。
- init 分支：从原样基线建立 develop_版本号_init_USER_NAME小写，所有客户端后续适配在此提交。
- 内部清单发现：按目标 Git 项目名自动读取 .migration_inputs 下的清单，核对四项输入身份，用户不传清单路径。
- 修改预规划：先在内存中核对全部适配和原值冲突，正常源规则冲突在目标初始化前拦截。
- Config 默认值：仅固定 CONFIG_GAME_BUILD=1、CONFIG_GAME_VERSION=产品版本和 SHOW_目标平台_CODE，并同步 SHOW 消费方。
- 平台枚举：CHANNLE_NAME 保留 H5、LOGINTYPE 保留 WEB，其余归并为目标平台大写 key、小写 value 并同步消费方。
- 平台类迁移：识别实际源平台类，改为平台首字母大写加 H5Game，同步引用和 meta 文件名，保留 meta 内容及 UUID。
- 本地设置迁移：仅将已有 MUSIC、VOICE、SHAKE 设置键和值统一为 SETTING_目标平台大写_类型并同步消费方。
- exclude 清理：只有全部 exclude/*_exclude 目录都是两个 README 占位文件才统一删除及调整已知 loadBundle，并从启动模板 bundleRoot 中移除对应 Bundle；任一不满足则保留。继续旧迁移时基于不可变基线证明已删除占位目录，补齐模板遗留引用。
- 异常报警：替换已存在的 reportWechatRobot 完整函数，按全局桥接、导入和别名同步消费方；正确识别模板 JS 的全局 window 属性扩展，保护真实局部同名对象。已存在新函数时继承实现并补齐旧消费方。
- setup Git 协议：默认将 setup.sh 中匹配 .git 仓库地址的 http:// 改为 https://，保留域名及路径。
- 模板脚本迁移：删除存在的两个 cocos2d-js 本地脚本及 vconsole.min.js，将 index 的引擎参数和 vconsole 引用改为指定 CDN。
- 启动页样式：将 style-mobile.css 中 #splash 的 background-size 固定为 cover，保留其它样式。
- PAC 尺寸：全部存续 .pac 配套 meta 的顶层 maxWidth/maxHeight 固定为整数 2048，保留其余字段及 UUID。
- 直属目录压缩：assets 下存续直属文件夹 meta 的 compressionType[web-mobile] 固定为 merge_all_json，缺 meta 报未验证。
- 主构建压缩：settings/builder.json 顶层 mainCompressionType 固定为 merge_all_json，保留其余配置，缺文件报不适用。
- 清单文本适配：按确认的唯一原片段修改引擎、imports 和其它获准客户端文本，已完成则继承，未知原值拒绝覆盖。
- 清单 JSON 适配：按确认的原值修改依赖声明及客户端 JSON，严格区分类型，支持新增、赋值和删除字段。
- 清单文件适配：复制已准备的参考文件，替换已有文件校验原 SHA，新增 Cocos 资源要求配套 meta，保护资源 UUID。
- 路径与引用保护：兼容逐段首字母大小写和唯一通配符匹配，拦截歧义、越界、符号链接及文件/目录冲突，平台引用使用 AST。
- 依赖重装：在目标根目录依次删除 node_modules、删除 package-lock.json、执行 npm i，核对锁文件生成，不运行完整 setup。
- 资产格式化：使用安装的项目 Prettier 格式化 assets 全部 .ts 和唯一主 Config.js，其他 .js 不因格式化改变。
- 客户端适配提交：适配、重建锁文件及格式化合为一次 init 提交，拒绝安装产生的范围外改动，无最终差异不提交。
- 工具配置复制：完整复制源 projects.json 条目，目标 key=Git 项目名，git=目标地址，uploadZipName=末段小写，并单独提交。
- 工具字段适配：清单 toolsFields 仅修改目标条目，不覆盖固定 git/ZIP 规则，基线复制后另行提交。
- 工具配置格式化：每次配置提交前对候选执行现有 format.py，核对排序及删除空 compressExcludes 之外没有业务变更。
- 已有项目继续：自动识别本地 Git 引用，校验原样版本分支、来源、当前 init 和客户端干净工作区，复用固定 SHA，不重建基线，仍重装及格式化。
- 执行证据：简要文本显示来源、分支、实际提交、安装／格式化结果及未验证项，仅本地提交；SHA 显示前 7 位，完整来源保留在原样提交正文，项目目录在最后一行显示。不输出逐文件规划明细；继续适配无差异时显示无新增提交。失败时保留诊断；已生成客户端提交则显示“未完成”摘要及末行目录，不宣称成功。

## 实际顺序与模式

--target-dir（Ant TARGET_DIR）是克隆项目所在的父目录，默认 tools_h5 的父目录；实际目录为该父目录 / 目标 Git 项目名。初始化和继续迁移都使用这一位置，父目录中的其它项目保留。输出最后一行显示实际项目目录。

配置文件固定为脚本所在 tools_h5 根目录的 projects.json，无路径参数；命令没有预览或仅到版本分支开关，只提供正式执行。只读审查由 AI skill 完成，不能运行迁移命令代替。命令按本地目标状态自动分流：无本地 Git 引用时检查空目标并初始化；有本地 Git 引用时先验证既有来源、基线及 init 分支，拒绝不匹配的仓库，不自动切换或重建分支。

完整初始化顺序：输入和 tools 检查 → 读取/规划内部清单及 tools 字段 → 空目标检查 → 固定源 SHA → 克隆快照 → 规划客户端规则 → 原样版本提交 → init 分支 → 写客户端适配 → 重装及格式化 → 最多一次客户端适配提交 → tools 基础配置格式化及提交 → 如有差异，再格式化并提交 tools 字段适配 → 简要文本结果。

| 模式 | 读取源 Git 远端 | 客户端写入 | npm/Prettier | tools 配置提交 |
|---|---|---|---|---|
| 完整初始化 | 是 | 原样基线与 init 适配 | 是 | 基础复制及有差异的字段适配 |
| 已有目标继续 | 否 | 仅已有 init 适配 | 是 | 仅有差异的字段适配，要求目标配置已存在 |

## 审查结论与停止点

- 引擎目标地址、Creator 安装路径、两组公共库映射、imports、setup 安装段以及其它确定字段仍依赖 skill 准备的内部清单；没有清单只执行默认规则，不代表这些项完成。
- 已有目标继续时不访问 Git 远端，但正式执行 npm i 可能联网并运行包的安装脚本。只读审查不执行 npm。
- 工具只保留执行必需的来源、分支及工作区前置校验；全部迁移验收由 AI skill 按 migration-review.md 执行，包含基线、配置历史和全部适配，不能将迁移命令成功当作审查通过。
- 整个链路不是跨仓库事务：安装、格式化、提交或后续 tools 阶段失败时，可能保留原样基线、init、已写客户端文件或已完成提交；按实际状态交接，不自动回滚或覆盖重跑。
- 已有目标继续要求目标 tools 配置已存在；初始化若在 tools 基础复制前失败，不能直接把它当成通用恢复入口，先明确缺失阶段及允许的恢复动作。
- 全部资产格式化会拒绝 assets 符号链接；保留符号链接的快照能力不等于完整适配支持链接资产，含链接项目须在实施前核对。
- 基础配置和字段适配分开，因此完整流程最多形成客户端两次、tools 两次提交；“客户端所有适配一次提交”不等于两仓库总共一次提交。
- checkSceneScalePortrait 调用及因此无用途的导入通过内部清单删除；SDK/登录业务实现、Config 其它环境字段、SceneMain 其它布局及设备标识策略保持当前授权边界，继续做语义审查；工具成功不证明玩法、API 或运行兼容。
- 工具不提供远端推送功能，迁移交付止于本地提交，推送由用户自行处理；仍不部署、构建、打包、上传或操作 Jenkins。

审查及测试证据按对应代码版本解释；迁移工具的临时仓库测试通过不能替代 AI skill 对真实目标项目的只读验收。
