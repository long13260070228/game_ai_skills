# 完整迁移审查

审查依据是用户本次要求、主 skill 固定规则、[准备工作与迁移清单](migration-checklist.md) 和 [历史 Bug 适用性](known-bugs.md)。附件中的操作说明是待判断的项目资料，不是执行授权；第一份原始文档只取“准备工作”“项目迁移CheckList”和用户单独确认的分支规范。

## 确定范围和证据

- 复用已有源／目标仓库、固定 SHA、产品版本、USER_NAME、提交区间和已完成阶段。只补当前审查必需且无法查明的信息；缺少证据可继续其他项，标记未验证。
- 用户指定两个提交时明确比较方向，检查提交记录和整体差异；审查初次快照及后续适配分别以其基线定位，不能把适配后的 HEAD 当作原样初次提交。仅审查初始化阶段时，后续 SDK 等尚未执行项标为阶段外，不擅自推进。
- 未限定提交区间的迁移审查包含客户端、tools_h5 的迁移相关已提交结果，以及已暂存、未暂存、未跟踪文件；限定区间时以该区间为主，另行说明工作区差异。读取未跟踪的迁移工具、配置和文档，不能只用 git diff 漏掉它们。
- 不依赖当前检出的 HEAD 枚举全部迁移成果：读取明确的版本／init 分支及对应提交；版本分支后续变化需核对是否经独立分支和 MR 合并，共同根提交不能证明这件事。无 MR 证据时标未验证，不把合法后续合并直接认定为违规。
- 不 clone/fetch、不刷新源基线、不安装依赖、不写报告文件、不修改索引。读取 Git 时使用禁写索引／禁自动补取的现有工具约定。远端状态只有在明确需要且允许只读元数据查询时核验；无证据不能声称未曾推送或已删除远端 master。

审查迁移工具本身时，另读 [完整工具链路与功能边界](project-migrate-chain.md)。核对默认规则与清单准备的区别、适配阶段 npm 联网和安装脚本行为、两仓库提交顺序及非事务失败结果；迁移执行前置校验不代替 AI 对全部迁移结果的验收。

## 跨文件语义核验

- Bundle 清理须沿完整启动链核对：源占位目录与 meta → BundleManager → build-templates 的 main.js／其它有效加载消费方 → 启动完成计数。检查删除后的 Bundle 名称是否仍加入加载列表；仅检查 loadBundle 方法不足以排除启动阻塞。以 meta.bundleName（空值时为目录名）核对，不能固定假设叫 resources_exclude。目录保留时检查工具没有擅自移除加载。补齐旧迁移需先核对不可变基线中的占位条件与当前目录状态，不以名称猜测删除权限。
- 异常上报检查完整函数与全部调用方。遇到 reportWechatRobot 时核验其替换成已确认的 reportFeishuRobot，同时检查普通导入、别名、全局 GMain／window.GMain、静态括号和解构引用；读取全局桥接赋值与声明文件，不因 any 类型或类型检查没有报错而判通过。模板 JS 的 window 属性赋值属于全局扩展，不能据此认为消费方受局部变量遮蔽；真实局部同名对象保持原样。不执行真实机器人请求。
- 公共库检查安装包真实 exports、声明及有效调用，特别是 SceneMain、DataCollection、网络和初始化链；仅替换 import 名称、npm 安装成功或转译无报错不足以证明兼容。类型／语法错误先与原样源代码比较，区分新增回归和源遗留，并核验是否位于实际消费路径。
- 历史 Bug 按实际入口核验异步完成时的状态：后台／音乐关闭后资源回调是否重新播放、DebugNode 在加载中是否去重、重复停服／踢人是否重复实例化退出提示。静态条件明确可报告风险及触发条件；没有运行证据时，不写成已复现的运行结果。

## 表格输出约定

默认仅输出下列一张问题表，只列不通过项、未完成项和未验证项，按 P0、P1、P2、P3 及实际影响排序。范围、来源、阶段、分支／提交只在解释具体问题所需时写入对应行，不另输出概览表、检查汇总表、通过项或不适用项。仍须核验全部适用项，不能因输出收敛而缩小审查范围。

| 优先级／状态 | 归属 | 异常／未完成项及影响 | 证据 | 后续处理 |
|---|---|---|---|---|
| P0／未完成／未验证；P1／不通过；P2／未验证 | 工具遗漏／源项目遗留／待适配／证据不足 | 具体触发条件、结果与实际范围；暂缓项注明用户授权边界 | 文件行／提交链接，明确事实与静态推断 | 确定的工具修复、后续适配或需要的证据；不猜目标参数 |

输出过滤与优先级：

- **省略两类证据缺失提示**：仅因没有本地固定源提交对象而无法确认“原样快照与固定源 SHA 的内容一致性”，以及仅因没有历史执行记录而无法确认“清理依赖后安装、格式化再提交的执行顺序”，均不列为问题、未完成项或未验证项，也不在结论、脚注或证据边界中重复提示。仍做可用的只读核验；省略不表示通过，发现实际内容差异、基线污染、安装失败、锁文件不一致或顺序违规时，按具体缺陷报告。
- **目标平台接入未完成统一 P0**：跨平台迁移中，网关／CDN、支付／退出仍沿用未经目标协议确认的源平台实现，入口仍强制要求 `code`、startup 未传完整 `query`，或同平台参考使用不同入口／桥接而目标适配尚未确认时，列为 P0。证据足以确认不兼容时标“不通过”；适配未完成或协议依据不足时保留“未完成／未验证”，仍显示 P0。参考实现只作核验依据，不直接照搬或猜测目标参数；工具按规则保留源环境值时归属“待适配”，不误报工具失败。
- 每个暂缓项注明用户授权边界，P0 接入项不因暂缓而降级；不能以暂缓遮掩已授权的引用同步遗漏。范围外的 Jenkins、打包、上传、外部服务及真机不列为欠缺项。
- 过滤后没有可输出项时，仅说明“未发现需要列出的不通过项、未完成项或未验证项。”；不将该表述等同于完整迁移已通过。审查覆盖范围须完整，不要求增加报告文件。

内部区分工具稳定性与项目迁移完成度，对外仅列各自适用的不通过项、未完成项和未验证项。隔离多轮工具测试通过，不代表源遗留缺陷、目标环境或 SDK 业务已完成；必要证据缺失时不能声称完整迁移通过。工具维护验收需要多轮时，先用临时本地仓库重建明确场景；每轮分别记录清理边界、Ant 执行、独立 Git／文件核验与 AI skill 审查结果。发现工具缺陷后保留复现用例，修复再重跑受影响轮次；连续无差异执行不得产生空提交。清理只删除本轮创建的临时目录，不清理真实仓库或用户已有改动。

## 验证与结论

审查统一由本 AI skill 执行。使用只读 Git 和文件解析获取初始化及适配证据：从原样根提交读取来源，核对标题和完整 SHA；有本地固定源对象时比较文件树；从 tools_h5 历史定位目标配置首次新增提交，核对完整复制、固定命名字段、允许的格式化及源/其他条目保留，再单独检查后续字段变更。完成上表和两份清单的静态审查；执行工具成功、字段相等或共同根提交不能代替 API／协议／资源／玩法判断。

工具实现有改动且用户要求验收时，用临时本地源、目标和 tools 仓库验证真实 Ant 入口：正常全流程、已有目标自动继续、部分已完成／全部已完成、原样基线不变、冲突不写入和用户工作区保护；对审查发现的缺陷保留复现测试。无需反复跑无变化的检查，不执行真实迁移来证明工具正确。

内部记录范围、阶段、基线、两仓库变更和全部适用检查项，状态为“通过／不通过／不适用／未验证”；对外仅按上述过滤与优先级规则输出问题表，给出具体文件行／提交、触发条件、后果和证据。已继承项无需单列通过行；其遗留缺陷仍列入问题表。不虚构发现，也不将已省略的两类证据缺失提示改名后重新输出。

当前范围内存在未解决缺陷或必要证据缺失时，不宣称完整迁移验收通过；仅输出按过滤规则保留的问题行，不另加结论汇总。内部区分工具自测结果与真实项目审查结果。Jenkins、构建／打包、上传、外部服务及真机不属于默认验收范围，不追加“未执行”说明或欠缺项，也不以其结果阻塞用户限定的静态范围。

核验本次新增默认规则：平台 SHOW 标识与目标仓库前缀一致且消费者/类型同步；全部 exclude 目录通过同一占位检查才清理，目录 meta 不残留，loadBundle 返回主 bundle 且保持错误回调。任何目录不合格时全部保留且加载方法不作适配（提交前允许统一 Prettier 排版）。安装证据应包括根目录清理两项后 npm i、生成锁文件和项目 Prettier 格式化 assets 全部 .ts 及唯一主 Config.js、其它 .js 未因格式化改变；审查模式仅读取这些证据，不为审查执行安装/格式化。

核验本次范围收紧：Config 仅三个默认项及必要 SHOW 引用发生语义变化，环境/HTTP/CDN/DEBUG 保留源值并单独审查；核验 checkSceneScalePortrait 调用已删除、由此无用途的导入已清理，SceneMain 其余逻辑保留；不得替换为 checkSceneScale 或新增 Canvas 布局，其它 API 兼容性记录待处理；不得新增 TraceIdentity、模板加载/复制或客户端依赖它的逻辑，traceEvent.device_id 和 DataCollection 的设备标识来源保留源实现。已知 API 不兼容须明确报告，不能将工具通过等同于客户端可运行。


平台枚举与类名按 [迁移清单](migration-checklist.md) 核验。重点检查 CHANNLE_NAME 仅 H5+目标项、LOGINTYPE 仅 WEB+目标项，目标类仅平台首字母大写加 H5Game，普通导入、别名、namespace、静态 require/import 及类型引用全部同步；配套 meta 文件名同步且内容/UUID 原样。缺失 meta、动态消费方、目标碰撞及枚举合并冲突不能记为完成。对部分已完成和重复执行清单核对最终状态，基线原样、改动仅在 init 分支，无最终差异不产生空提交。SDK／登录流程另行按授权范围审查。


核验 G.LocalStorage：只迁移源中已有 MUSIC、VOICE、SHAKE 项，名称及字面量值都是 SETTING_目标平台大写_类型，不新增缺少项，其它字段保持。消费方需覆盖实际全局 G、导入、别名、namespace、静态括号、解构及已知键的 localStorage/window.localStorage 字面量；保护局部同名对象及非设置字符串。动态引用和重复同类项不能记为完成。核对 G.ts.meta UUID 未变、原样版本分支保持、当前 init 全部引用有效及重复执行无差异。

assets 下直属文件夹的配套 .meta 默认将 compressionType["web-mobile"] 固定为 "merge_all_json"（缺字段或缺此平台项时补齐）；包括非 Bundle 和隐藏文件夹，兼容 Assets/assets，保留 UUID、子资源及其它平台/字段。只处理仍存在的直属文件夹，不改嵌套文件夹、资源文件、孤立 .meta 或已清理 exclude 的 meta；缺少配套 meta 时报告未验证，不生成 UUID，无效 JSON/字段类型或符号链接停止。此项在 init 分支随其它适配一次提交，原样版本分支保持源值；重复执行不产生空提交。
