# H5 项目迁移

覆盖客户端和独立工具集合 `tools_h5` 的迁移配置。Jenkins、构建触发、打包验证、发布及真机验收不属于默认范围；不以这些工作作为完成条件，也不声称它们已经通过。

迁移流程仅生成客户端与 tools_h5 的本地提交，不提供远端推送功能；远端推送由用户自行处理。

## 执行与审查模式

“迁移／继续实施”沿下面阶段推进；“审查／检查迁移／比较提交”进入只读审查模式，读取 [完整迁移审查](references/migration-review.md)。审查覆盖当前阶段内全部迁移相关内容，包含客户端、tools_h5、源项目已完成事项和两者的对应关系；不只查看适配清单列出的文件，也不以初始化工具通过代替完整审查。

审查结果默认仅输出一张问题表，只列不通过项、未完成项和未验证项，按影响排序；不输出范围／来源概览、通过项或不适用项，但仍完成全部适用项核验。具体格式与过滤规则见完整迁移审查；区分工具缺陷、源项目遗留、待适配及证据不足，不把暂缓业务或范围外验证归为工具失败。

不输出仅因证据缺失而无法确认的“原样快照与固定源 SHA 的内容一致性”和“清理依赖后安装、格式化再提交的执行顺序”提示；这不等于判定通过，发现实际差异或顺序违规时仍报告。目标网关／CDN、支付／退出仍沿用未经目标协议确认的源平台实现，以及入口仍强制要求 `code`、startup 未传完整 `query` 等目标平台接入未完成项，统一列为 **P0**；缺少目标协议证据时保留“未验证”状态，不省略优先级、不猜目标值。

只读审查不进入实施阶段，不修复、不提交、不推送。用户另行要求处理问题或自测验收时，只在已授权范围修复及验证；工具验收使用临时本地仓库，不对真实项目试跑迁移。已有仓库、提交区间和上下文足够时直接审查，不为审查机械要求重填四项迁移输入。

审查 project_migrate 完整链路、列功能或维护工具时，读取 [完整工具链路与功能边界](references/project-migrate-chain.md)，从当前 Ant/Python 入口逐层核对实际实现；区分默认规则、skill 内部清单项与 AI skill 审查职责，不把支持执行的清单分组当作已经自动准备或实际执行的功能。

## 输入约定

每次必填四项；可接受同义表达，不要求用户重填已有信息：

```text
源仓库：
源分支：
目标仓库：
版本号：
```

- 版本号由产品提供，保留原值，不自行升级或补齐版本位数。
- 复用 Ant 的公共参数 `USER_NAME`（init 分支用其小写）、`tools_h5 地址或本地路径`；用户明确提供用于复用的值可记入 [defaults.yaml](references/defaults.yaml)。`USER_NAME` 未设置时不得用 Git 作者名、旧开发者拼音或 `unknown` 替代；仅在完整初始化需要它时补齐，继续不依赖它的只读工作。
- `特殊要求`、`平台参考项目` 可选。未指定参考时，先在目标平台现有项目中查找可复用实现，核验协议和已知问题；不把参考项目当作无条件正确的模板。
- 从目标仓库地址识别平台与仓库名，例如 `h5newgame_client_wheel` 对应 h5newgame。先查目标平台参考和 tools_h5 现有配置，再判断游戏标识、协议、房间及上传参数是否缺失；不猜测。
- 缺失输入只列当前阶段无法可靠查明且会阻塞工作的值。勘察前的可查配置列为“待核验”，不是要求用户填报的清单；已识别的平台和可选参考项目不追加为必填项。

## 固定规则

| 项目 | 规则 |
|---|---|
| 源基线 | 获取用户指定源分支的远端最新完整提交 ID，固定本次基线；不要求用户提供 SHA，不回落其他分支，不混入源工作区改动 |
| 目标仓库 | 新仓库；克隆指定源分支最新代码，移除克隆副本根目录的 `.git`，复制剩余全部文件和文件夹（含隐藏项），再提交；不迁入源历史、分支或标签 |
| 客户端版本分支 | `develop_版本号` |
| 客户端初次提交标题 | `项目迁移 【源Git项目名 源分支 源SHA前7位】`，例如 `项目迁移 【liveme_client_pharaohTreasure master d6e070f】`；正文记录完整来源信息 |
| 默认客户端适配 | Config.js 中 build=1、version=产品版本、SHOW_目标平台_CODE；平台枚举、类名及 meta/消费方同步；G.LocalStorage 的已有设置统一目标平台命名并同步消费方；全部占位 exclude 目录满足条件才统一清理和改 loadBundle；在 init 分支提交，不修改原样版本基线 |
| 迁移初始化／开发分支 | 从版本分支检出 `develop_版本号_init_USER_NAME小写`；首次与版本分支指向同一提交，后续适配在此分支进行，不额外创建默认 transplant 分支 |
| 常规功能分支 | `父分支名_功能名_人名`，蛇形命名；版本号中的点按产品原值保留 |
| 测试修复分支 | 从版本分支检出 `develop_版本号_人员名`，不得在版本分支直接修 Bug |
| tools_h5 | 使用 `master`，不套用客户端的 `develop_*` 命名 |

目标 URL 是仓库身份的依据；仓库名称规则与分支命名分别处理，不擅自改用户给定的仓库 URL。

## 按阶段推进

始终保留当前阶段、已完成事项、固定基线及待确认项；恢复工作时核对现状，从未完成项继续。每阶段简要报告进展，不重复索要已知输入。用户要求一次只做一步时，只完成当前阶段。

### 1. 收集与只读勘察

复用现有输入和公共配置，读取相关仓库规则、README、分支及工作区状态。源分支仅用于选择最新代码版本，以用户输入为准。执行模式下查询该远端分支最新提交并固定 SHA；本地缓存不是最新基线的证据。不为迁移收集源仓库全部分支或旧版本历史。

当用户要求“只讨论”“只读审查”时，仅查看已有文件和远端元数据；不 clone/fetch、初始化仓库、写配置或状态文件，也不执行 setup/install。无法联网时说明尚未确定远端最新提交，不以本地 SHA 替代。

### 2. 复制最新代码与建立版本分支

只在用户已要求实施迁移时进入。固定的项目复制、版本分支初次提交及 `projects.json` 基础配置复制已抽离为 `tools_h5` 中的命令；读取 `src/migrate/migrateProject.py --help` 与 `build.xml` 的 `project_migrate` 入口，复用它，不在 skill 中另写一套克隆和复制实现。

```bash
ant project_migrate -f "<tools_h5路径>/build.xml" \
  "-DSOURCE_REPO=<源仓库>" "-DSOURCE_BRANCH=<源分支>" \
  "-DTARGET_REPO=<目标仓库>" "-DPROJECT_VERSION=<版本号>" \
  "-DUSER_NAME=<已确认的公共用户名>" \
  "-DTARGET_DIR=<克隆目标项目所在的父目录>"
```

脚本位于 `src/migrate/migrateProject.py`，参数以 `--help` 为准。命令只提供正式执行，没有预览或仅到版本分支模式；只读审查由 AI skill 读取 Git、文件和必要的纯解析结果完成，不能通过运行迁移命令代替。执行前按第 1 阶段核验授权、输入和工作区。配置文件固定使用脚本所在 tools_h5 根目录的 projects.json，不接受路径参数。目标尚未初始化时执行完整迁移；已有本地 Git 引用时核验来源、原样版本基线、当前 init 分支及干净工作区后继续适配，不用额外模式开关。常规模式在客户端初次提交后建立 init 分支，然后完整复制源配置条目：目标 key 等于 Git 项目名（不含 `.git`），替换 `git`，`uploadZipName` 自动取目标 key 最后一个 `_` 后面的部分并转为小写。其它平台配置仍按第 4 阶段核验和适配。

Python 的 --target-dir（Ant TARGET_DIR）指定父目录，默认 tools_h5 的父目录；实际项目目录固定为该父目录下的目标 Git 项目名（去掉 .git），不能传项目目录本身或自定义项目目录名。父目录可含其它项目，也可尚不存在；新迁移和继续适配都按同一规则定位。结果最后一行显示实际项目目录，不移动旧目录或猜测历史路径。

执行前核对已有迁移阶段和用户改动；来源或分支不匹配、客户端工作区脏状态及继续适配时已有 tools 目标配置所在文件有改动时停止，不将现有仓库当作新仓库覆盖。新增迁移仅以工作区 projects.json 不含目标配置判断配置冲突；tools_h5 其它暂存／未暂存改动以及 projects.json 内其它条目的改动不拦截。工具用临时索引仅提交本次目标条目和既有格式化规范，保留用户原有暂存／未暂存内容，不夹带其它文件或配置改动。不得为使检查通过而自动撤销用户暂存、删除目标或重复初始化；先核对已完成阶段。

读取命令的简要文本结果，记录来源、客户端分支／初次提交、默认客户端适配提交、tools_h5 配置提交（若执行）、安装／格式化结果、未验证项及最后一行的项目目录。显示的 SHA 为前 7 位，完整源 SHA 从客户端原样提交正文核验；继续适配时只报告本次新增提交，无差异显示无新增提交。命令失败且已生成客户端提交时，读取“未完成”摘要和最后一行项目目录，核对实际完成阶段，不重复初始化或覆盖已有成果；子模块及未下载 LFS 等未支持情况不得报告为成功。常规模式即使未提供清单，也执行默认客户端适配；提供清单时还执行已确认的其它定点适配，不替代准备工作判断、客户端迁移清单、历史 Bug 核验或后续语义审查。

**安装依赖、修改 setup、全局格式化、平台替换、报告文件均放在原样初次提交之后。**

当前命令不提供只到版本分支的执行模式；用户限定这个停止点时，不能调用完整正式迁移命令超出授权范围，先只读勘察并交接入口能力限制。若之前已停在版本分支，只有用户要求继续后才补建上述 init 分支，并在新目标仓库删除不再需要的 `master`；不重跑初始化命令覆盖已有结果。不操作源仓库的分支。新仓库若含自动初始化文件或实际已有业务历史，先解释与代码快照初始化的冲突，不覆盖或强推。

### 3. 客户端迁移

迁移路径逐段兼容首字母大小写，如 script/Script、configLib/ConfigLib、Config.js/config.js；保留实际名字，不通过重命名来统一。其它清单路径可用通配符，已有文件必须唯一匹配；新增路径中不存在的目录段及文件名须明确。重名、别名、跨出项目或通过符号链接的匹配不得继续修改。

读取 [migration-checklist.md](references/migration-checklist.md)，建立“来源要求／适用条件／修改位置／验证证据／状态”的对应清单。结合 [known-bugs.md](references/known-bugs.md) 核验源项目已有修复，仅补入适用缺陷和本次需求。

build-templates 默认适配：存在时删除 cocos2d-js.js、cocos2d-js-min.js、vconsole.min.js；index.html 的引擎 loadScript 第一个参数整体替换为 `https://hkres.qigame1024.com/h5sdk/v1/cocos2d-js-min.fcae2.js`，不再按 debug 选择本地引擎；vconsole 引用改为 `https://hkres.qigame1024.com/h5sdk/v1/vconsole.min.40fd7.js`。style-mobile.css 中 #splash 的 background-size 改为 cover，保留其它 CSS。处理实际目录大小写和已完成项，在 init 分支适配；不下载 CDN 资源或执行构建。

工具对主 Config.js 仅修改 CONFIG_GAME_BUILD、CONFIG_GAME_VERSION、SHOW_目标平台_CODE，保留其它字段及环境原值；清单不得通过整文件复制或文本操作修改其它 Config 内容。网关、HTTP/CDN、DEBUG 等由完整 skill 审查并交接，不自动实施。遇到 checkSceneScalePortrait 调用时直接删除，并清理因此不再使用的公共库导入；通过已确认内部清单执行，不替换成 checkSceneScale 或新增 Canvas 布局逻辑。保留 SceneMain 其它逻辑，不添加 TraceIdentity 或改变 traceEvent/DataCollection 的设备标识策略；其它 API 或设备标识问题记录待处理。

确定性的迁移修改复用 `project_migrate` 自动读取的内部适配清单，Ant／Python 不接受用户提供清单路径。内部存储约定见 [工具链路](references/project-migrate-chain.md)，具体清单格式核对已有 `src/migrate/internalAdaptation.py` 和 `migrationAdaptation.py`；由 skill 按目标 Git 项目名在工作区 `.migration_inputs/<目标Git项目名>/adaptation.json` 准备 inputs+recipe 包裹，使用既有 repoIdentity 记录四项输入身份，参考文件与清单一起放在客户端之外。命令会核对输入身份；不让用户创建 JSON 或填写路径。按真实源代码和目标依据形成内部 JSON 清单：引擎配置、依赖声明、已核验的 imports 映射、客户端文本/JSON 字段、明确的平台文件及 tools_h5 目标字段；不要求用户新增一套必填输入。清单须在调用完整迁移命令前准备于目标项目之外，写文件不能污染原样基线。用户要求完整实施时，先逐项核对全部适用迁移项并准备已确认的适配清单；默认客户端规则及基础配置复制完成，只能报告该阶段完成，不能据此报告完整迁移验收通过。已有目标结果仍不能重跑初始化覆盖。

源项目可能已完成部分工作：逐项核对实际目标状态，已满足则继承；当前值与确认的原值、目标值都不一致时报告冲突，不降级、不机械重做；按用户要求在本次目标资产目录格式化，不修改其它项目。引擎目标地址、Creator 路径、公共框架与性能监控两组映射、imports 和 setup 安装段依赖内部清单准备，不是无清单自动推断项；分别按迁移清单核验，不能因当前项目只有一组依赖而漏掉另一组通用规则。客户端适配在 init 分支独立提交，工具配置基础复制与目标字段适配也分开提交；无差异不产生空适配提交。API、锁文件、SDK 回调与玩法正确性仍须核验，不能用字段相同或“已完成”状态代替。

默认平台适配按 [迁移清单](references/migration-checklist.md) 的平台规则执行：从实际 platformGame 实例导入识别源类；CHANNLE_NAME 保留 H5、LOGINTYPE 保留 WEB，并统一目标平台项。目标类仅平台首字母大写加 H5Game，同步所有引用及 meta 文件名，保留 UUID。动态/冲突/缺失配套资源需交接；这些已授权的标识和值调整不扩展 SDK／登录流程。

直属文件夹 meta 的 web-mobile 压缩默认规则按迁移清单执行：固定 merge_all_json，保留 UUID 和其它字段；不改嵌套文件夹、资源 meta 或已清理的 exclude。缺少配套 meta 只报告，不生成 UUID。

PAC 与主构建压缩默认规则由同一 project_migrate 执行：全部 `.pac` 配套 `.meta` 的顶层 maxWidth/maxHeight 固定为整数 2048；settings/builder.json 的顶层 mainCompressionType 固定为 merge_all_json。保留 UUID、子资源及其它字段，已完成项跳过；PAC 缺少或损坏 meta、builder 无效 JSON 时停止，builder 缺文件报告不适用。兼容路径首字母大小写，无额外用户参数；只在 init 分支适配，原样版本分支保持源值。审查须按迁移清单核对全部适用文件，不能用工具自测代替真实项目验收。

G.LocalStorage 的已有 MUSIC、VOICE、SHAKE 按迁移清单统一目标平台命名，键和值都更新；缺少的项不新增。审查全局桥接及全部消费方，保留其它存储项与局部同名对象；不复制旧缓存，不用全局字符串替换。

平台标识和 Bundle 方法复用已有 TypeScript AST 纯解析（项目、tools_h5 依赖或已安装 tsc），不执行客户端脚本；缺少解析能力时报告前置条件，不用字符串替换绕过语义核验。重复全量文件清单以最终默认规则和项目 Prettier 的只读 stdin 规范化内容比对；只有最终相同才继承，其它差异仍拒绝覆盖。

project_migrate 默认在全部适配后、init 提交前，在目标根目录依次删除 node_modules、删除 package-lock.json、执行 npm i，然后用安装的项目 Prettier 格式化 assets 下全部 .ts 和唯一主 Config.js（实际路径大小写、项目配置、忽略 prettierignore 排除；其它 .js 不格式化）。这两步与适配、锁文件一起一次提交，不需要另行手动执行；失败停止，不产生适配及后续配置提交。只读审查不运行安装/格式化；不运行 setup.sh 的全局引擎操作，仍不构建或推送。无最终差异时不产生空提交，安装成功不代表 API 或运行验收通过。整体不是跨仓库事务；失败可能留下基线、init、未提交客户端文件或部分提交，先核对实际阶段，不擅自回滚或重跑初始化。assets 含符号链接会被提交前格式化保护拦截，须在实施前识别。

同一批已授权客户端适配先完整准备并完成可独立执行的静态／隔离验收，再将完整清单交给 project_migrate 一次执行，形成一次适配提交；不要按文件组连续调用来拆分提交。执行后再核对真实结果和幂等性。若已提交后才发现遗漏，如实说明原因，补齐并验收；不因用户询问提交次数而擅自重写已有历史。

初始化后可以继续补充已授权适配。明确列出尚未执行的可工具化操作；不能因工具已经支持这些操作而报告实际迁移已完成。之后客户端适配必须在已有 `develop_版本号_init_USER_NAME小写` 分支上执行和提交，保留版本分支原样基线。后续客户端及 tools_h5 提交直接描述实际改动，不加“项目迁移”前缀；仅客户端原样初次提交使用上述来源格式。已有目标继续适配复用同一入口，由工具自动识别本地 Git 状态；工具自动读取已确认内部适配清单，无清单时仍可执行默认规则：核对本地来源、原样版本基线及当前 init 分支，不访问 Git 远端、不重建初始化结果；正式适配仍执行 npm i，可能联网并运行包安装脚本，不能称为离线执行。目标 tools 配置必须已存在，初始化在基础配置复制前失败时不能直接继续适配恢复。命令规划阶段核验已有客户端值，源中已完成项仍跳过。用户暂缓 SDK／登录等某项时，执行已授权的平台枚举值、类名及资源引用调整和依赖一致性所需的 imports／符号映射，不扩展其业务流程，不删除它仍使用的模板桥接。tools_h5 后续字段适配继续在其 master 单独提交。

保持玩法不变量，优先修改已有平台抽象和配置。目标服务器、协议或产品参数不能从可信依据确认时，暂停依赖该参数的改动并继续独立项。参考项目和文档示例不得直接覆盖源玩法逻辑。

### 4. tools_h5 配置

确认这是独立仓库，并使用 `master`。沿其 README 和现有入口找到 `projects.json` 及调用方，复用对应平台、相近游戏配置，更新实际所需的仓库、标识、名称、路径和图片压缩配置。

明确的语言、上传目录、压缩排除项和 Bundle 路径修改可放进适配清单 toolsFields，优先复用该入口；字段含义和目标值仍由本阶段确认，不猜测、不自行发明字段。仅修改配置与必要文档，不新建同义打包脚本，不改 Jenkins。工作区有用户改动时先保护并隔离本次配置修改，不重置或夹带提交。

添加或适配配置后，必须先执行 `python3 ./tools/format/format.py`，再本地提交 projects.json。迁移工具复用该脚本，对候选配置格式化并核验后提交；只读审查不执行格式化。脚本会排序全部配置并删除空 compressExcludes，这些既有行为是用户要求的规范化例外，审查时单独记录，不误报源条目／其他项目被业务修改。其它字段完整保留。

### 5. 静态核验与交接

迁移验收统一通过本 AI skill 按 [完整迁移审查](references/migration-review.md) 逐项执行，不调用独立审查工具。用只读 Git、文件读取及必要的无副作用解析收集来源、唯一根提交、版本/init 分支、全部默认与清单适配、安装格式化证据及 tools_h5 配置历史；已有本地源仓库含固定 SHA 时比较 Git 文件树。不能把 project_migrate 的执行前置校验或成功输出当作完整验收。按实际阶段裁剪检查项，不为审查补建分支或配置；缺少源码、历史或运行证据时记未验证，不 clone/fetch 补取。

核对：原样基线、分支命名、旧平台有效残留、标识和协议一致性、SDK/回调引用、资源 meta、多语言、环境配置，以及客户端与 tools_h5 配置的对应关系。可执行明确无构建、压缩、上传副作用的配置解析和局部静态检查；不运行 setup/install 或打包入口来冒充只读验证。

审查内部记录客户端与 tools_h5 的分支／提交、检查状态及证据，状态使用“通过／不通过／不适用／未验证”；对外按完整迁移审查的过滤规则，仅输出不通过项、未完成项和未验证项的问题表。运行、打包、真机和外部系统不属于默认审查范围，不列为欠缺项，也不阻塞本范围完成。

迁移完成时交付本地分支、提交和审查结论，远端推送由用户自行处理。用户另行要求创建 MR 时，使用 GitLab 的实际可用入口，不调用只支持 GitHub 的 PR 工具代替，也不自动推送分支。测试修复通过独立分支和 MR 回版本分支；更新状态、通知测试只按用户实际授权执行。

## 易错点

- 不把其他文档的默认源分支覆盖用户指定分支；基线冻结后源分支更新不自动漂移。
- “只复制最新代码”采用克隆指定分支、删除临时副本 `.git`、复制剩余全部内容并提交的流程，隐藏文件和隐藏目录同样复制。源 SHA 只作来源记录，不代表导入源提交历史。
- 不因文档“所有项目已修复”而跳过目标代码核验，也不将历史代码片段机械替换成新公共库名称后直接使用。
- 不为了“保证安全”扩展到 Jenkins、打包验证或全仓无关重构。
- 创建、编辑或测试本 skill，不等于开始实际项目迁移；明确的只讨论／只读限制优先。
